# 微博 × 大众点评：预制菜知情权文本采集与编码

本目录服务于专题第二部分的大样本平台比较。**目前没有完成微博与大众点评的大样本采集，因此不能生成两平台的占比图。** 既有 85 条抖音评论及公开论文的汇总数据均不进入本比较的分母。

## 采样设计

- 对象：微博公开帖文及其公开评论；大众点评北京餐厅公开评价。两种文本类型分别记录，最终图表分别报告分母，不把帖子与评论混算。
- 时间：建议固定同一连续 12 个月窗口；正式采集前在 `study.json` 填写起止日并冻结，不因结果调整。
- 检索词：`预制菜`、`预制菜知情权`、`预制菜需不需要公开`、`现炒`、`料理包`、`中央厨房`。查询词须与餐饮场景组合；排除纯零售商品广告与无关内容。保留每条命中的查询词。
- 大众点评：先冻结北京餐厅抽样框及门店 ID，再采集评价。不能仅按“预制菜”关键词筛选，否则会高估主动提及预制菜的人群。
- 目标：每个平台至少 1000 条**去重、人工核对来源、按同一本编码手册完成编码**的文本；两个平台须报告抽样框、检索覆盖、拒采和缺失数量。达标仍不能代表平台所有用户或北京总体。
- 议题可多选：`安全`、`价格`、`口味`、`加工方式`、`知情权`、`便利`、`校园`。立场、先前是否知情、是否描述亲历另行编码；不根据情绪词推断店家确实使用预制菜。

## 输入格式

`records.csv` 或 JSONL，每条包含：

`platform,kind,url,record_id,text,published_at,collected_at,query,restaurant_id,restaurant_name,city,source_method,verified,topic_codes,stance,prior_knowledge,first_person`

- `verified` 只能由核对过原页面或可靠平台导出的人员填 `yes`。
- `topic_codes` 用 `|` 分隔；`stance` 为 `支持/接受`、`反对/不满`、`条件接受`、`中性/询问`、`无法判断`；`prior_knowledge` 为 `事前知道`、`事前不知道`、`无法判断`。
- 可先用 `suggest` 生成**待复核**的议题提示，提示不进入正式统计。
- 不保存账号密码、Cookie、手机号、昵称等个人信息。引用原声前检查是否会识别个人，并保留原始链接及访问日期。

## 命令

```bash
python3 pipeline.py template records.csv
python3 pipeline.py suggest records.csv suggested.csv
python3 pipeline.py audit records.csv
python3 pipeline.py report records.csv report.json
python3 collect_public.py public_urls.csv collected/
```

`report` 仅在两个平台均达到上述门槛、每条记录来源已核对且关键编码完整时产生正式比较；否则输出 `status: blocked` 与缺口清单，绝不补造数值。

`collect_public.py` 只对预先列出的公开 URL 抓取 HTML 和页面元数据，遵守 robots、每站请求间隔和访问限制，输出 `fetched_unverified` 线索。它不能发现全站样本，也不会自动把页面摘要当作评论。公开 URL 清单 CSV 的列为 `platform,url,query,restaurant_id,restaurant_name,city`。

## 采集路径与当前限制

1. 优先使用平台授权的研究/商家接口或平台允许的导出；把导出结果映射到上述格式。美团点评开放平台的评价接口与业务/商家权限相关，并非任意餐厅的公开全量接口。
2. 可用公开 URL 做人工核验与原声链接，但搜索引擎索引只覆盖部分页面，不能当作大样本抽样框。
3. 当前运行环境访问大众点评域名失败，微博公开页面访问受限；没有可用的平台授权凭证或可验证的大样本导出。工具不会绕过验证码、登录、访问控制或限流。具备授权访问或平台导出后即可导入、核验和统计。

## 统计解释

同一条文本可有多个议题，所以各议题百分比之和可以超过 100%。`report.json` 的议题分母为该平台所有合格文本；立场和知情状态各自单选。平台之间的图只说明**所定义样本**的差异，须同时展示时间、地域、文本类型、检索方式和样本量。
